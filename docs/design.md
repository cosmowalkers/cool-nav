# Cool Nav · 设计文档

> 首版定稿：2026-09-28，一轮「14 个问题」的需求访谈后确定，V1 按此实现并构建通过。
> 同日追加两轮：壁纸/背景图落地，数据层加固。现状见「实现现状」，改过的判断在正文里就地更新。

## 一句话

把 Edge 的新标签页换成自己写的极简导航页：**一行搜索 + 一屏铺平的快捷方式**，数据存在浏览器本地、跟着账号跨电脑同步。

## 定位与边界

- **形态**：MV3 扩展，用 `chrome_url_overrides.newtab` 接管新标签页；侧载自用，不上架商店
- **平台**：只做 PC。手机端主动砍掉——手机浏览器装不了自制扩展，硬做网页版还要面对国内托管可达性的坑
- **产物**：`dist/` 里就是全部（一个 HTML + manifest + 图标），无后端、无部署、无 service worker
- **不做**（每一条都是主动砍的）：
  - 全量导入浏览器收藏夹（715 条只用于挑预置，不搬进来）
  - 天气、待办、稍后读、RSS、便签
  - 新闻 / GitHub trending 等信息流模块（会把这页从「工具」变成「内容消费入口」）
  - 账号体系、自建云同步（改用浏览器自带的 `storage.sync`）
  - 回收站与撤销（兜底手段是导出 JSON）

## 关键决策与理由

- **真接管新标签页只能靠扩展**：Edge 消费版设置里没有「新标签页指向自定义网址」的入口；官方策略 `NewTabPageLocation` 在 macOS 上仅对 MDM/MCX 纳管设备生效。所以要么写扩展，要么接受「只是启动页」
- **背景默认纯色渐变，壁纸是可选开关**（首版写的是「不做壁纸」，后改为现在这样）：壁纸是第一眼差异点，但新标签页一天看几十次，惊艳感很快衰减成视觉噪音，且带图要额外照顾每处文字的可读性、是最容易做丑的一条路。折中做法是——默认用内置风景图集（只存 id、按屏幕物理像素拼尺寸，不吃带宽），不想带图时切回程序化渐变（零图片资源、秒出），图片类来源一律配蒙版兜可读性
- **链接铺平，不做分组**（后改的，数据结构第 2 版）：分组的价值在于「扫描时不用读全部」，但真实用量就十几条，分组的成本（建组、起名、跨组拖拽、组名占位）明显高于收益——一屏本来一行就摆得下，分组反而把它切碎。以后链接真多起来，靠搜索框找，而不是靠分组兜
- **预置只给 8 条**：预置是种子不是搬运。剩下的备选整理成 `docs/seed-links.json`（45 条），想用再导入
- **浏览态零按钮**：编辑态与浏览态彻底分离。编辑一天只用一次，可以糙；浏览态是天天看的，必须干净
- **搜索做「开发者版」但不做联想**：多引擎 + 前缀直达 + 智能跳转 + 本地搜索历史。联想依赖各家私有接口，属于「做的时候能跑、三个月后悄悄坏掉」的功能，砍掉后扩展版与网页版体验也一致
- **键盘导航按视觉位置走，不做数字直达**：链接的键位应该是「我看到哪块就是哪块」。`Tab` 交给浏览器原生顺序，方向键用矩形中心算最近邻——网格是居中排的，DOM 顺序和视觉位置不一定一致；数字直达（`1`~`9` 打开第 N 个）不做，链接顺序会变，键位和位置对不上反而难记，真要按名称找就该用搜索框
- **图标用浏览器原生 favicon API**：`chrome-extension://<id>/_favicon/?pageUrl=…`，零外部请求、零隐私外泄，效果等同标签栏图标。不用 Google s2 这类第三方服务（国内直连不通，且等于把访问域名报给第三方）
- **图标绝不落库**：`storage.sync` 只有 100KB / 单条 8KB，几百个 base64 图标瞬间撑爆配额
- **技术栈**：Vite + Vue 3 + TS + **Tailwind v4**（`@tailwindcss/vite`，设计 token 走 `@theme`，深浅色靠同名 CSS 变量覆盖）+ vue-draggable-plus；不引组件库（默认视觉会跟极简打架，最后全是 `!important`）、不引 Pinia（全局只有一份数据，一个 composable 足够）
- **不写 service worker**：新标签页本身就是扩展页面，天然有 storage / favicon 权限，抓标题也能直接在页面里 fetch

## 数据模型

同步区（`storage.sync`）两个键，避免单条超过 8KB：

- `nav`：`{ version, settings, links[] }`，`links[]` 是 `{ id, title, url, icon? }`；`links` 的顺序就是屏幕上的顺序
- `history`：最近 30 条搜索词

`settings` 四项：默认引擎、显示时钟、记录搜索历史、背景 `{ preset, url, rotate, scrim }`。
`preset` 取值：`none | aurora | dawn | ink`（内置渐变）、`scene`（内置风景图集）、`image`（自己粘的链接）、`local`（本机图库）、`bing`（每日一图）。

本机区（`storage.local`，不上云、不进导出）：`images`（图库 dataURL 数组）、`bing`（每日一图缓存 + 日期）、`wallpaper`（当前这张 + 切换时间，用来跨新标签页延续）。

**第 2 版的迁移**：第 1 版按 `groups[].links[]` 存。读取时两种结构都认——见到 `groups` 就按分组原顺序 `flatMap` 铺平成 `links`，随后立刻把新结构落盘（`links` 一旦存在就优先信它）。导出的旧 JSON 也能直接导入，走的是同一条路径。

写入策略（后两轮加固的，都是为了让新标签页不丢数据）：

- 深度监听 + 400ms 防抖（拖拽排序会高频触发）
- **内容没变就不写**：和最近一次落盘的内容比对，省 `sync` 的写入配额
- **限流自动重试**：`MAX_WRITE_OPERATIONS` 这类失败等 5s 再写，不把这几分钟的编辑丢掉；真配额满才提示先导出备份
- **坏数据不覆盖**：读出来的内容一律过一遍 normalize；有数据但读不出来时回退预置链接并给提示，不覆盖原值
- **跨标签页 / 跨设备采纳**：别人写了就跟着变，但本地有未落盘改动或正在编辑时不抢，避免两边互相覆盖

## 视觉规范

- 主色只用**一个**强调色：浅色 `#4b6bfb` / 深色 `#7c95ff`；跟随系统深浅色
- 背景：浅色 `#f6f6f4`（米白，不用纯白）、深色 `#16171a`（近黑深灰，不用纯黑）；有背景图时整体切到 `#0b0d14` 那一套并锁深色文字体系
- 时钟 76px、字重 200、等宽数字；日期 12.5px 带 0.2em 字距；链接名 12.5px
- 图标底板 44px / 圆角 14px；瓦片宽 96px；瓦片之间 `gap-x-1 gap-y-2.5`
- **版式：头部顶部锚定，不做整块垂直居中**：离顶 `clamp(64px, 13vh, 140px)`（矮屏不至于贴边、高屏也不至于跑到中间）。整块居中的问题不是不好看，而是链接一多整块就往上顶、位置还随数量漂移，加两条链接整页都在动；锚定之后加链接只往下长
- 搜索框 `max-w-[560px]`、高 50px、圆角 15px
- 焦点环只有一套语言：强调色描边 + 3px 外圈。输入框 55% / 15%，瓦片更小又常压在图上，加重到 80% / 35%
- 搜索框在壁纸上走毛玻璃（18px blur）；下拉面板（搜索历史、设置）用实底——里面全是小字，透一点就会和壁纸细节糊在一起
- **兜底色板只保留 8 个色相**（214/245/268/292/330/12/32/168），由域名 hash 决定，同站恒定。早期版本直接 hash 出 360 个色相，会出现橄榄绿、土黄这类脏色

## 交互规范

- `/` 或 `Cmd/Ctrl+K` 聚焦搜索框；`E` 切换编辑态；`Esc` 退出编辑 / 清空搜索框 / 关弹窗（弹窗开着时 `E` 不再切底层编辑态）
- 搜索框自动聚焦（新标签页的默认动作就是输入）；输入像网址就直接跳转，否则用默认引擎搜；前缀 `gg / bd / bz / gh / npm` 直达对应引擎；上下键 + 回车选历史
- 点链接用当前标签打开（新标签页本身是空的，留着没意义）；Cmd/Ctrl+点击仍按浏览器默认开新标签
- 键盘导航：搜索框里按 `↓`（没有历史联想时）进第一块瓦片；瓦片之间 `←→↑↓` 走、`Enter` 打开、`Esc` 回搜索框；`Tab` 仍按浏览器原生顺序走。
  上下移动按几何最近邻找「正对着的那一块」，所以行宽不同的居中排版下，`↓` 再 `↑` 不一定回到出发的那一块——换来的是换行之后永远落到眼睛看着的那一块
- 设置面板：点搜索框右侧引擎名展开，「搜索」tab 放引擎/时钟/历史，「外观」tab 放背景来源、轮换、蒙版
- 背景轮换四档：每次新开 / 每小时 / 每天 / 不切换；每 60s 检查一次是否到点，切换前先预取下一张，取不到就跳过，别把页面弄成空屏
- 编辑态：整块网格自由拖拽排序、列表末尾是「+ 添加」瓦片、瓦片右上角删除；导入 JSON 覆盖前二次确认
- 添加链接时先抓网页标题做名称，抓不到（或网页版环境）就回退成域名

## 实现现状

已实现并构建通过：搜索（多引擎 / 前缀 / 智能跳转 / 历史）、铺平网格与拖拽、编辑态、导入导出、
背景（渐变 + 风景 + 每日一图 + 本机图库 + 图片链接，含轮换与蒙版）、时钟、深浅色、键盘导航。
未做：链接过滤、多套配置切换、侧栏 widget。见「V2 候选」。

## 踩坑记录

- **入场动画的 `animation-fill-mode` 只能用 `backwards`**：用 `both` 会让 `transform` 一直挂在元素上，该元素就成了层叠上下文，下拉面板的 `z-index` 会被困在里面，站点图标会压到面板上面
- **多标签页会互相覆盖**：新标签页经常同时开着好几个，在 A 里编辑会用 A 的旧数据整份写回去，把 B 刚加的链接抹掉。光靠「打开时读一次」不够，得监听 storage 变化
- **存储内容不能直接强转**：早先 `stored.groups as NavGroup[]` 一遇到写坏的数据就让整页打白，读进来必须过一遍校验再进内存
- **换数据结构不能直接覆盖**：从分组改成铺平，是「读的时候两种都认、读到旧结构就顺手落盘」，而不是开一版把老数据丢掉——同步区里那份数据是几台机器共用的，直接覆盖等于把还没升级的那台清空
- **同步写入有限流**：`storage.sync` 每分钟写入次数有上限，拖拽这类高频操作会撞上；写失败不能只弹个提示就完事，得自动重试
- **壁纸先预取再切**：`Image.onload` 之后再淡入，否则新开标签页会先闪一下白底
- **焦点环不能照抄输入框那套**：搜索框的「描边 55% + 外圈 15%」在 560px 的大框上够看，照搬到 44px 的瓦片上、还压在壁纸上，1x 之下基本看不见。瓦片这套得加重到描边 80% / 外圈 35%
- **隐形的可聚焦元素是个坑**：右上角铅笔平时 `opacity: 0`（只靠 hover 显形），但它一直在 Tab 序里——键盘走到这儿就是个看不见的焦点。凡是 hover 才显形的控件，都得补 `focus-visible` 显形规则

## 已知边界

- 抓标题需要 `<all_urls>` 权限，装的时候浏览器会提示「读取所有网站数据」——自用侧载无所谓，上架会被审核问；网页版环境跨域会失败并回退成域名
- 浏览器没缓存过某站 favicon 时可能取不到图，落到色块，不会空着
- 删除不可撤销，只能靠导出 JSON 兜底
- 「本机图库」和「每日一图」缓存都在 `storage.local`，不参与同步、也不会出现在导出的 JSON 里，换台电脑需要重新收集
- 图片写入前统一缩到 2400px、转 WebP，单张几百 KB；几十张没压力，再多要自己删
- 无头环境下无法验证扩展态（Chrome 已禁止用命令行加载解包扩展），需要人工在 `edge://extensions` 里加载 `dist/` 确认
- 不支持手机端：手机浏览器装不了自制扩展，这是当初主动砍掉的范围

## V2 候选（都还没做）

- **链接过滤 / 直达**（优先）：铺平以后链接一多就只能靠搜索框找——输入时先在链接里过滤，命中就把「打开 xxx」排在最前
- **多套配置一键切换**：工作 / 个人两套链接与搜索引擎，一键换
- **侧栏 widget 面板**：GitHub 用官方 Search API 近似 trending、HN 官方 API 做新闻。优先级最低——容易把「工具」变成「内容消费入口」
