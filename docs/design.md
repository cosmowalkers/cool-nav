## 一句话

把 Edge 的新标签页换成自己写的极简导航页：**顶部纯色带命令面板搜索框 + 中栏文本行链接 + 右信息栏（时钟 / 天气）**，
数据存在浏览器本地、跟着账号跨电脑同步。

## 定位与边界

- **形态**：MV3 扩展，用 `chrome_url_overrides.newtab` 接管新标签页；侧载自用，不上架商店
- **平台**：只做 PC。手机端主动砍掉——手机浏览器装不了自制扩展，硬做网页版还要面对国内托管可达性的坑
- **产物**：`dist/` 里就是全部（一个 HTML + manifest + 图标），无后端、无部署、无 service worker
- **不做**（每一条都是主动砍的）：
  - 全量导入浏览器收藏夹（715 条只用于挑预置，不搬进来）
  - 天气、待办、稍后读、RSS、便签
  - 新闻 / GitHub trending 等信息流模块（会把这页从「工具」变成「内容消费入口」）
  - 账号体系、自建云同步（改用浏览器自带的 `storage.sync`）
  - 回收站与撤销（兜底手段是导出 JSON）

## 关键决策与理由

- **真接管新标签页只能靠扩展**：Edge 消费版设置里没有「新标签页指向自定义网址」的入口；官方策略 `NewTabPageLocation` 在 macOS 上仅对 MDM/MCX 纳管设备生效。所以要么写扩展，要么接受「只是启动页」
- **背景：每日一图默认，自定义图片可选，纯色兜底**（这条被推翻过三次，留着看演进）：首版「不做壁纸」→ 第二版「内置图集 + 程序化渐变」→ 第三版「自己打包一套风景图，按搜索引擎切」→ 现在这版。最后一版推翻了前两版的假设：**自己打包图片这条路不划算**——6 张图就是 1.2MB 包体，还得自己挑图、自己扛版权，而这些图对「新标签页要快、要干净」毫无贡献。所以内置图整包删掉，默认交给 Bing 每日一图（天天换、零包体、微软自己维护），想固定就用一张自己的图链接，接口挂了或没给图就是纯色底。附带好处：整个扩展不再有任何图片资源，商店审核也不用解释图源（09-29 另补：改版后背景只铺顶部那一条，正文永远压在纯色上，早先的蒙版方案已经整个去掉）
- **每日一图也得先问权限**（09-29 追加）：它是默认背景，很容易顺手写成「必装 host 权限」——装的时候能直接拿到图，代价是安装提示里出现「读取你在 bing.com 上的数据」。改回可选权限后，没权限时**一次请求都不发**：顶图那一条铺按引擎固定的底色，搜索框下面给一个「点这里允许」的入口（这次点击本身就是手势，正好用来申请）。宁可默认差一点，也不把权限塞进安装流程
- **位置只按出口 IP 推断，定位权限整个砍掉**（09-29 定稿）：浏览器定位这条路在国内不值得走——Chromium 在系统定位拿不到坐标时会退回 Google 的定位服务，那个服务不可达，于是把系统权限全开也只会拿到「设备定位不可用」。既然精度本来就只能到城市级，那就干脆用 IP 反查（同一个 BigDataCloud 无参接口），省掉一个权限项和整条不确定性；代价是出差、挂代理时会推错城市，所以卡片上必须标明「按出口 IP 推测」（后来干脆把手填入口也删了，只留一个刷新按钮）
- **走导航站的排布：分组 + 文本列表**（第 3 版，试过再改回来的）：中间试过铺平（第 2 版），理由是「分组成本高于收益」——那条判断在十几条链接时成立，但铺平有两个问题：大屏上一行摆满、横向空间浪费，链接一多又全糊成一片没有结构。导航站那套（分组标题 + 紧凑文本行 + 自动分列）密度高、扫读快，一屏能放几十条，且不需要更大的图标尺寸。所以最后是「分组 + 文本行」而不是「分组 + 大图标瓦片」：瓦片信息量低、占地大，是这一版换掉的重点
- **日期信息放在时钟下面那一行**：天气、农历、节日、假期状态这些一天看好几次，是最值得占那 20px 的信息；再多的内容（逐小时预报、空气质量、预警）会把新标签页变成天气 App，不做
- **农历交给浏览器，节日调休走官方数据**：农历用 `Intl.DateTimeFormat('zh-CN-u-ca-chinese')`——ICU 维护、含闰月和干支，自己维护年份表既占体积又容易错；调休日历必须用官方口径（周末规则解释不了「10 月 10 日这个周六要上班」），取 `holiday-cn`（按国务院办公厅通知手工维护，文件里带通知原文链接）；天气用 Open-Meteo（免 key、有 CORS）。timor.tech 那类聚合 API 实测已经被 Cloudflare 人机验证挡在门外，不能用
- **预置放通用站点，不放私人链接**（09-29 改）：要上架应用市场，预置只能是所有人都用得上的公开站点，按「一天里打开的频次」排——常用 / 开发 / AI / 资讯 / 工具 / 生活 六组 34 条。公司内网、个人知识库这类一律不进预置（要留在自己机器上就走导入）。官方预置之外的备选整理成 `docs/seed-links.json`（35 条），同样是公开站点，想用再导入
- **浏览态零按钮**：编辑态与浏览态彻底分离。编辑一天只用一次，可以糙；浏览态是天天看的，必须干净
- **搜索做「开发者版」但不做联想**：多引擎 + 前缀直达 + 智能跳转 + 本地搜索历史。联想依赖各家私有接口，属于「做的时候能跑、三个月后悄悄坏掉」的功能，砍掉后扩展版与网页版体验也一致
- **学 Arc 不能只学一个输入框：候选得按 frecency 排**（09-29 补）：命令面板的壳子早就有了，但结果一直按
  「当初把链接写进导航的顺序」排——链接越多面板越难用，等于把 Arc 最值钱的那一半漏掉了。
  现在每次打开链接记一笔（`linkStats`，只存本机、只留 200 条），命中按「打开次数 ÷ 距今时间」重排，
  空面板先给「最近打开」。代价是多一份本机行为数据，收益是这个面板会跟着使用习惯变准
- **键盘导航按视觉位置走，不做数字直达**：链接的键位应该是「我看到哪块就是哪块」。`Tab` 交给浏览器原生顺序，方向键用矩形中心算最近邻——网格是居中排的，DOM 顺序和视觉位置不一定一致；数字直达（`1`~`9` 打开第 N 个）不做，链接顺序会变，键位和位置对不上反而难记，真要按名称找就该用搜索框。
  （10-08 修订：加了一档**跳分组**——焦点在链接区按 `1~9`、或全局按 `Alt+1~9` 跳到第 N 组第一条，`⌘/Ctrl+↑↓` 跳首尾；按组跳键位跟组序绑定而不是跟链接编号绑定，组序稳定，和当初「不做数字直达」的理由不冲突）
- **图标用浏览器原生 favicon API**：`chrome-extension://<id>/_favicon/?pageUrl=…`，零外部请求、零隐私外泄，效果等同标签栏图标。不用 Google s2 这类第三方服务（国内直连不通，且等于把访问域名报给第三方）
- **原生 favicon 取不到时，直接跟站点要 `/favicon.ico`**（09-29 补）：`_favicon` 只认浏览器**已经缓存过**的图标——没在这个浏览器里打开过的站点，缓存里就是没有，于是整条导航有一半显示成色块，看起来像「图标功能坏了」。这跟网速无关，跟「你访问过没有」有关。现在的顺序是「自定义图标 → 浏览器缓存 → 站点自己的 `/favicon.ico` → 首字母色块」；最后一步只发往用户自己放进导航的站点，不经过任何第三方图标服务（这是当初拒掉 Google s2 的底线）。补不到的域名记进 `iconMiss`，7 天内不再重试——新标签页一天开几十次，不能每次都拿用户和站点的带宽去撞同一堵墙
- **猜不到路径的，就编辑态点一次「补全图标」**（09-29 再补）：`/favicon.ico` 只能救「图标在根目录」的那批，像 vuejs.org（`/logo.svg`）、npmjs.com（CDN 上的图）这种声明在 HTML 里的怎么猜都猜不到。浏览器不给扩展读网页内容的权限，就只能去要：编辑态那个按钮**一次性申请 host 权限**（用户点的那一下就是授权时机），然后并发（4 路、上限 40 条、同域名只访问一次）抓每个还没有图标的链接的 HTML，把 `<link rel~="icon">` / `shortcut icon` / `apple-touch-icon` 解析成绝对地址写进 `link.icon`。写进链接之后图标就**不再依赖浏览器缓存**，跟着 `storage.sync` 走。这是「隐私优先」和「图标要好看」之间唯一说得通的位置：权限是用户点出来的、请求只发往他自己放进导航的站点、不经过任何第三方
- **图标绝不落库**：`storage.sync` 只有 100KB / 单条 8KB，几百个 base64 图标瞬间撑爆配额
- **技术栈**：Vite + Vue 3 + TS + **Tailwind v4**（`@tailwindcss/vite`，设计 token 走 `@theme`，深浅色靠同名 CSS 变量覆盖）+ vue-draggable-plus；不引组件库（默认视觉会跟极简打架，最后全是 `!important`）、不引 Pinia（全局只有一份数据，一个 composable 足够）
- **不写 service worker**：新标签页本身就是扩展页面，天然有 storage / favicon 权限，抓标题也能直接在页面里 fetch

## 数据模型

同步区（`storage.sync`）两个键，避免单条超过 8KB：

- `nav`：`{ version, settings, links[] }`，`links[]` 是 `{ id, title, url, icon? }`；`links` 的顺序就是屏幕上的顺序
- `history`：最近 30 条搜索词

`settings` 五项：默认引擎 `engineId`、亮暗色 `theme`（system / light / dark）、显示右侧信息栏 `showSidePanel`、记录搜索历史 `historyEnabled`、背景 `{ preset, url }`。
`preset` 取值只有两个：`none`（纯色，默认）、`image`（自己粘的图片链接）。旧值（`bing` 等一切历史背景）读到时统一迁到 `none`。
纯色就是页面底色，不加蒙版；自定义图片铺在顶部那一条，也只是一串地址，图片本身不落库。

本机区（`storage.local`，不上云、不进导出）：`weather`（30 分钟）、`geo:<城市>`（城市 → 经纬度）、`holiday:<年份>`（调休日历，7 天刷新；跨年那几天会把次年的也读进来拼一起）、
`linkStats`（`linkId → { 打开次数, 最后一次打开 }`，只留最近 200 条，用来给命令面板排序；这是本机的使用痕迹，没有上云的必要）。

**结构换代的迁移**：读取时 `groups` 和 `links` 都认——有 `groups` 就正常读（v1 的组结构和现在一样，只把版本号补写成 3）；只有 `links`（v2 铺平数据）就把它包进一个「常用」分组，随后立刻落盘。导出的旧 JSON 走同一条路径，两个版本的备份都能直接导进来。

写入策略（后两轮加固的，都是为了让新标签页不丢数据）：

- 深度监听 + 400ms 防抖（拖拽排序会高频触发）
- **内容没变就不写**：和最近一次落盘的内容比对，省 `sync` 的写入配额
- **限流自动重试**：`MAX_WRITE_OPERATIONS` 这类失败等 5s 再写，不把这几分钟的编辑丢掉；真配额满才提示先导出备份
- **坏数据不覆盖**：读出来的内容一律过一遍 normalize；有数据但读不出来时回退预置链接并给提示，不覆盖原值
- **跨标签页 / 跨设备采纳**：别人写了就跟着变，但本地有未落盘改动或正在编辑时不抢，避免两边互相覆盖

## 视觉规范

> 09-29 第四次改版后按「键盘优先效率导航」重写：无左栏、无卡片块，站点改文本行。

- 主色只用**一个**强调色（10-08 起：深色复刻 Ghostty 的 Chester `#2c3643` 底 / 青 `#27dede` 强调，
  浅色复刻 Atom One Light `#f9f9f9` 底 / 蓝 `#2f5af3` 强调）；跟随系统深浅色
- 背景：浅色 `#f9f9f9`、深色 `#2c3643`；右栏卡片浅色 `#ffffff` / 深色 `#3b444f`
- **字号**：正文 14px、分组标题 18px / 600、站点名 14px / 500、次要信息 12px、时间 32px / 300 等宽数字
- **版式**：容器 `max-w-[1400px]`、`gap-3`；两栏 = 自适应中栏 + 270px 信息栏（`xl` 起出右栏）。
  中栏直接铺在页面底色上，右栏 `sticky top-3`
- **顶图**：纯色（即页面底色），高 `clamp(96px, 15vh, 128px)`；选了自定义图片才在那一条铺图。
  搜索框 `760×52`、圆角 12px、实底 `--color-surface` + 细边框，垂直居中
- **站点文本行**：无边框，`px-2.5 py-2`，`gap-1`；一条只有「18px 图标 + 14px/500 名称」，
  hover/焦点才上底色；行内格栅 `repeat(auto-fill, minmax(150px, 1fr))`，1400px 下约 6~7 列
- **分组标题行**：18px 标题在左，`N 个` 在右（14px `--color-faint`），下面 `mb-2` 再进格栅
- **焦点环只有一套语言**：输入框是「3px 强调色外圈」；站点行是「底色 + 3px 强调色外圈」
- 搜索框与命令面板都用实底——命令面板里全是小字，透了会糊
- **亮暗两套色板只写一份**：值写成 `light-dark(浅, 深)`，切哪个由 `<html>` 上的 `color-scheme` 决定。
  跟随系统时 `color-scheme: light dark` 就够了，显式选亮/暗时 `useTheme` 写 `data-theme` 覆盖。
  好处是没有第二份 token 要对齐，也不会有「改了浅色忘了改深色」这种漏
- **兜底色板是 8 组写死的孟菲斯色**（洋红 / 橘 / 芥末黄 / 青柠 / 湖绿 / 天蓝 / 靛蓝 / 紫），由域名 hash 决定，同站恒定。
  更早的版本要么直接 hash 出 360 个色相（出现橄榄绿、土黄这类脏色），要么按色相现算 `S 54% / L 57%→40%`（出来是砖红、土黄那类灰扑扑的颜色）——
  颜色这件事最后还是得一组一组挑，算不出来

## 交互规范

- `/` 或 `Cmd/Ctrl+K` 聚焦搜索框；`E` 切换编辑态；`Esc` 退出编辑 / 收起命令面板 / 关弹窗（弹窗开着时 `E` 不再切底层编辑态）
- 搜索框即命令面板：聚焦展开，输入时结果分「链接 / 命令 / 历史 / 搜索」四块，上下键移动、回车执行；
  输入像网址就直接跳转，否则用默认引擎搜；前缀 `gg / gh` 直达对应引擎
- **有输入时命令面板默认选中第一项**，回车即执行——Arc 的命令栏一直有一项高亮，不然每次都得先按一次 `↓`，
  键盘优先省下来的那点时间又还回去了。空输入时故意不选：新标签页是自动聚焦的，
  默认选中「进入编辑模式」等于回车就误入编辑态
- 空输入时命令面板先列**「最近打开」**（最近开过的 5 个链接），再列最近搜索 + 命令
  （进入编辑、切换主题、切换搜索引擎、导入导出、补全图标）——Arc 的空命令栏给的就是这个，不是一屏命令
- 链接命中按 **frecency** 排序：命中条数一样时，打开得越勤、最近打开过的那条排前面，和「当初把它写进哪个分组」无关
- `Cmd/Ctrl + Enter` 在面板里用新标签页打开（和浏览态 `Cmd/Ctrl + 点击` 链接同一个语义），高亮行右侧会提示
- 编辑态按 `Enter` 与鼠标点击一致：打开编辑弹窗，不做跳转（以前按回车会直接把网页打开）
- 点链接用当前标签打开（新标签页本身是空的，留着没意义）；Cmd/Ctrl+点击仍按浏览器默认开新标签
- 键盘导航：搜索框里按 `↓`（空输入，命令面板没有可移的结果）进第一条链接；链接之间 `←→↑↓` 走、`Enter` 打开、
  `1~9` / `Alt+1~9` 跳分组、`⌘/Ctrl+↑↓` 跳首尾、`Esc` 回搜索框、`?` 调快捷键帮助；`Tab` 仍按浏览器原生顺序走。
  方向键按几何最近邻找「正对着的那一条」，所以多列排版下 `→` 换列、`↓` 换行，列对齐时上下往返是严格的。
  编辑态补充：`Delete` 删、`N` 新建、`⌘/Ctrl+←→` 排序、弹窗 Esc 关闭后焦点回到触发链接
- 设置面板：点搜索框右侧引擎名展开，「搜索」tab 放引擎 / 历史，「外观」tab 放主题、背景（纯色 / 自定义图片）、右侧信息栏开关
- **位置只用出口 IP 推断，不碰浏览器定位**（09-29 定稿，前面那套「点按钮申请高精度定位 + 精度门槛」已经删掉）：
  国内 Chromium 在系统定位不可用时会退回 Google 的定位服务，而那个服务不可达，于是把系统权限全开也只会拿到
  `POSITION_UNAVAILABLE`；这条链路上投入的每一步（申请权限、判精度、给指引）都在跟一个用户改不了的外部依赖较劲。
  现在的做法是：`api.bigdatacloud.net` 的无参接口按调用方 IP 反查城市，卡片上标明「按出口 IP 定位」，
  只留刷新按钮、不支持手填。代价是出差/挂代理时会推错城市，收益是少一个权限、少一堆不确定性
- 天气取数的地点解析：「到点自动刷新」沿用上次解析出的坐标（省一次请求），
  手动刷新（force）时重新按 IP 解析
- **天气要显示到区/县**：IP 反查（BigDataCloud）自带 `locality`（区县），直接透传显示；
  有就给「天津 · 西青区」这种显示；拿不到就只显示市
- 编辑态：组名直接改、跨组拖拽、删除按钮常显、中栏末尾「新建分组」、删除分组前明确告知会连带删掉几条链接；导入 JSON 覆盖前二次确认
- **删链接不弹确认框，改成底部 6 秒撤销条**：编辑态一天点十几下删除，每次都问很烦；但删链接又是最高频的破坏性操作，
  所以给一次后悔的机会（`useNavData` 里只有一个撤销槽位，后来的顶掉前一个）。删分组仍然二次确认——那个动静太大
- 编辑态每组格栅的**最后一块是「添加」**：入口得看得见，不能只留下一条没人触发的 `emit` 声明
- 导入 / 导出从命令面板发起；补全图标也从命令面板发起（仍是「点击即授权」的手势路径）
- 添加链接时先抓网页标题做名称，抓不到（或网页版环境）就回退成域名

## 踩坑记录

- **重做版式时最容易丢的是「入口」，而且类型检查抓不到**：09-29 把瓦片版改成文本行时，`LinkSections` 里
  「添加」那个格子被删掉了，但 `emit('addLink')` 的声明和 `App.vue` 上的 `@add-link` 都还在——
  事件声明在、绑定在、类型全对，只是**没有人触发它**。结果编辑态只能改和删、加不了新链接，
  而且这个状态能一路构建通过。教训：删掉一个交互入口时顺手 grep 一遍它的事件名，
  另一头还挂着就说明漏了（和下面「DOM 标记别散着写」是同一类问题）
- **入场动画的 `animation-fill-mode` 只能用 `backwards`**：用 `both` 会让 `transform` 一直挂在元素上，该元素就成了层叠上下文，下拉面板的 `z-index` 会被困在里面，站点图标会压到面板上面
- **多标签页会互相覆盖**：新标签页经常同时开着好几个，在 A 里编辑会用 A 的旧数据整份写回去，把 B 刚加的链接抹掉。光靠「打开时读一次」不够，得监听 storage 变化
- **存储内容不能直接强转**：早先 `stored.groups as NavGroup[]` 一遇到写坏的数据就让整页打白，读进来必须过一遍校验再进内存
- **换数据结构不能直接覆盖**：分组↔铺平来回换过两次，做法都是「读的时候两种结构都认、读到旧结构就顺手落盘」，而不是开一版把老数据丢掉——同步区里那份数据是几台机器共用的，直接覆盖等于把还没升级的那台清空
- **DOM 标记别散着写**：把瓦片换成列表行时改了 `data-tile` → `data-link`，事件处理那边漏改一处，方向键和 Esc 就整个失效（表面上「没报错但没反应」）。标记抽成一个导出的常量、两边共用，就不会有第二次
- **CDN 会「挂着不回」，必须给每个源加超时**：调休数据的第一个镜像 `cdn.jsdelivr.net` 实测连接超时 95 秒（`ERR_CONNECTION_TIMED_OUT`），而 `fastly.jsdelivr.net` 是 1ms。不设超时的话，功能不是「失败」而是「一直不出现」，最难查。做法：按实测速度排镜像 + 每个 5 秒超时，再套本地缓存和「周末＝休息」的兜底
- **接口数据要被断言逼出来**：写 `statusOf` 时顺手把补班那天的假期名丢掉了（`off: false` 就不带 name），界面只能显示「补班」说不出为哪个假期调休——是对着构造数据写断言时才发现的。外部数据的字段语义（哪个字段是补班、名字挂在哪天）不写成断言就等于没验
- **同步写入有限流**：`storage.sync` 每分钟写入次数有上限，拖拽这类高频操作会撞上；写失败不能只弹个提示就完事，得自动重试
- **壁纸先预取再切**：`Image.onload` 之后再淡入，否则新开标签页会先闪一下白底
- **首屏别串上壁纸下载**：`main.ts` 原本是 `await Promise.all([initNav(), initWallpaper()])` 之后才挂载，而壁纸要等图片 `onload`——冷启动白屏 1.7s，图慢就是 7.8s。正确顺序是「数据先到位 → 挂载 → 壁纸后台跑」；数据仍然要等，不然会先闪一下预置链接。本机图片 + 人为延迟 2.5s 的对照：改前内容 2579ms 才出现，改后 28ms，壁纸照旧在 2539ms 就位
- **焦点环不能照抄输入框那套**：搜索框的「描边 55% + 外圈 15%」在 560px 的大框上够看，照搬到小控件上、还压在壁纸上，1x 之下基本看不见。链接行那套得改成「底色 + 更实的描边」
- **隐形的可聚焦元素是个坑**：右上角铅笔平时 `opacity: 0`（只靠 hover 显形），但它一直在 Tab 序里——键盘走到这儿就是个看不见的焦点。当时的补救是补 `focus-visible` 显形规则，但那治的是键盘、没治鼠标：真正的问题是**入口本身看不见**，最后直接改成常显图标（和主题按钮同款毛玻璃方块）。「浏览态零按钮」这条到这里作废——藏起来的入口等于没有入口，而一次点击的收益远大于那 30px 的干净
- **滚动高亮只看位置，会在「内容不够长」时失效**：左栏高亮算的是「top 已经滚过 96px 的最后一组」。点到最后一组时页面已经到底、滚不动了，那一组的 top 永远到不了 96px，游标就卡在上一组（点「生活」亮的是「AI」）。两处补丁：点击时先自己亮（页面完全不可滚时连 scroll 事件都没有），滚动到底且页面确实可滚时强制落到最后一组
- **「跟随滚动」不能真的跟着每一个 scroll 事件走**：点最后一组时，平滑滚动会经过前面每一组，高亮就跟着依次点亮 1→2→3→…→6，看起来像高亮在自己跑，交互很怪。根子上是把「中间过程」也当成了用户意图。现在的规则：点击是权威（`lockUntil` 600ms 内一律不重算，点击瞬间就亮），手动滚动则在**停稳 120ms 后**按落点更新一次——只有「落点」有意义，途中的位置没有
- **16px 图标要单独简化**：`C + 箭头` 在 128 / 48 下很清楚，缩到 16px 就糊成蓝点（矢量化后箭头只有 1.1px 粗）。做法是小尺寸单独一版：去掉箭头、把 C 加粗，48 / 128 仍用完整图形——扩展工具栏和商店页看到的本来就不是同一档
- **定位的「精度线」定错了等于没有**：早先拿 20 公里当「这是 IP 级定位」的门槛，结果实测那台机器拿到的粗定位置信半径只有 1~5 公里（网络定位给的是「城市级」结果，只是城市经常是隔壁机房所在市），照样显示成了错城市。门槛收到 3 公里，并且在右栏把「系统定位：已授权 / 精度不够 · 本次精度 ±N」直接摊开——否则用户根本不知道错在哪一层
- **扩展的定位权限没有运行时弹窗**：`geolocation` 写在 manifest 里，装的时候就一次性授予，`navigator.permissions.query` 直接返回 `granted`，所以「点按钮才请求」其实只挡得住调用，挡不住授权；真正决定精度的是 macOS 那一层（系统设置 → 隐私与安全性 → 定位服务 → 勾选浏览器）。代码侧能做的就是把状态和精度摆到界面上，让用户知道该去查哪一层
- **国内 Chromium 的定位会直接「设备定位不可用」**：报错是 `code 2`（POSITION_UNAVAILABLE），不是 `code 1`（权限被拒）——系统定位拿不到时，Chromium 会退回 Google 的定位服务，而这个服务在国内不可达，于是把系统权限全开也一样失败。这条没法在扩展里修，能做的就是给一条**明确标注的兜底**：按出口 IP 反查一个城市（BigDataCloud 同一个接口，不带坐标就按调用方 IP 查），当作「建议」渲染出来，用户点「用它」才落到设置里——绝不自动把 IP 城市当成定位结果直接显示
- **城市名进地理编码前要先「洗」一遍**：Open-Meteo 只认「天津」不认「天津市」，区县名（南开区）干脆没有结果；而「上海市」会匹配到美国伊利诺伊州那个同名小城。做法是原样查不到就去掉行政区后缀重查，输入含中文时优先 `country_code = CN` 的结果。这个坑是「IP 建议 → 点用它」那条链路第一次跑就撞出来的

## 已知边界

- 抓标题需要 `<all_urls>` 权限，装的时候浏览器会提示「读取所有网站数据」——自用侧载无所谓，上架会被审核问；网页版环境跨域会失败并回退成域名
- 浏览器没缓存过某站 favicon 时可能取不到图，落到色块，不会空着
- 删除不可撤销，只能靠导出 JSON 兜底
- 位置按出口 IP 推断（城市级），出差/代理会推错，天气卡上有个刷新按钮可以重试；不支持手填城市。扩展不申请定位权限，manifest 里的 `permissions` 只剩 storage + favicon。抓标题 / 补图标都要对应域名的可选权限：装的时候没有全量权限提示，用到的那一刻才问，不给就退回域名命名 / 继续靠浏览器缓存。网页版（`npm run dev`）没有这套 API、也跨域拿不到标题，会回退成域名
- 无头环境下无法验证扩展态（Chrome 已禁止用命令行加载解包扩展），需要人工在 `edge://extensions` 里加载 `dist/` 确认
- 不支持手机端：手机浏览器装不了自制扩展，这是当初主动砍掉的范围
- 天气与调休依赖外部接口：取不到时天气那格不显示、调休退回「周末＝休息」（这天到底放不放假就说不准了，但不会显示错数据）；次年的调休要等国务院办公厅 11 月前后发通知，`holiday-cn` 更新后本机会在 7 天内跟上
