## P0 · 功能缺口与 bug

### 1. 没有任何「添加链接」的入口（回归）

`LinkSections.vue:11` 还声明着 `addLink` 事件，`App.vue:121` 还绑着 `@add-link`，但模板里
**从来没有 emit 过它**；上一版 `EditBar`/`LinkSections` 里那个「添加」格子（`git show HEAD:src/components/LinkSections.vue:81`
`@click="emit('addLink', group.id)"`）在 09-29 这次重做里被删掉了。

结果：编辑态只能改和删预置的 34 条，加不了新链接，只能靠导入 JSON。这是目前最硬的功能缺口。

**建议**：编辑态每个格子末尾放一个 `+` 格（Arc 的 tile 布局里最后一块就是它），点击 → `openAddLink(group.id)`。
顺带解决「空分组」只能看到「空分组」三个字、没有任何下一步的尴尬。

### 2. 设置里的「显示右侧信息栏」是死开关

`nav.settings.showSidePanel` 只在设置面板里被写（`SearchBar.vue:538`），从没有代码读它——
`App.vue:130` 写死的是 `class="hidden self-start xl:block"`。

两个后果：勾掉它页面没反应；窗口宽度 < 1280px（`xl`）时时钟 / 农历 / 天气整块消失，而用户以为那个开关能救。

**建议**：`SidePanel` 的 class 跟着 `showSidePanel` 走；同时想清楚窄屏语义——是「窄屏强制收起」还是「窄屏改放到顶部一行」。

### 3. Esc 收起面板后，继续输入不会再弹出来

`SearchBar.vue:301-307`：第一次 Esc 走 `closeCommand()`（清空输入 + `commandOpen = false`），但**输入框仍然保持焦点**；
而 `commandOpen` 只在 `@focus`（`:365`）时置 true。于是「Esc → 继续打字」这条最顺手的路径直接失效。

实测复现：输入框里明明有 `git`，面板不出现（截图 02）。

**建议**：`@input="commandOpen = true"`，或把面板可见性改成「有焦点或有输入」；Esc 的语义保持「清空 + 收起」。

### 4. 面板默认没有选中项，Enter 不执行第一项

`activeKey` 初始是 `null`，`:293-300` 的 Enter 在没选中时走 `submit()`（默认引擎搜索）。
也就是：**每次打开面板都得先按一次 `↓` 才能执行第一项**，这一下按键的成本，正好抵消了「键盘优先」省下来的时间。

Arc 的命令栏永远有一项默认高亮，Enter 等于「执行高亮项」。

**建议**：面板可见且 `activeKey` 为空时，默认取 `flatItems[0]`。

### 5. 面板没有最大高度，也不能滚动

`:382-385` 那个面板 div 只有 `absolute` + 内边距，没有 `max-h` / `overflow`。
实测查询 `e` → 16 行、688px 高（视口 813px）；而上限是 8 链接 + 15 命令 + 6 历史 + 1 = 30 行 ≈ 1100px。
窗口矮一点、或者历史攒几条，面板就会顶出屏幕底部且滚不到（`overflow-y: visible`）。
配套问题：`moveActive()` 只改 `activeKey`，不 `scrollIntoView`，所以键盘能把选中项移到看不见的地方。

**建议**：`max-h-[min(60vh,520px)] overflow-y-auto` + 选中项 `scrollIntoView({ block: 'nearest' })`。

### 6. 删链接没有护栏，删分组有

`SiteCard.vue:76-87` 的 `×` 一点就删；而删分组走 `window.confirm`（`App.vue:64`）。
最高频的破坏性操作反而最没有保护，且「删除不可撤销 + 只能导出 JSON 兜底」是文档里承认的边界。

**建议**：不要加 confirm（每次都问很烦），改成 Arc 那种**底部撤销条**：`已删除「GitHub」· 撤销`，5 秒内可撤回。
这同时把「没有回收站」这条已知边界补上了一大半。

### 7. 编辑态按 Enter 会直接跳走

`SiteCard` 是 `<a href>`，编辑态只在 `@click` 里 `preventDefault()`（`:42-48`）。
所以编辑态里鼠标点 = 打开编辑弹窗，键盘 Enter = 打开网页，同一格两种行为。

**建议**：编辑态不渲染 `href`（或整条改成 `<button>` 语义），Enter 同样进编辑弹窗。

### 8. 面板里不能「在新标签页打开」

`activate()`（`:215-227`）一律 `window.location.href`，并且列表项用 `@mousedown.prevent`，
所以 Cmd/Ctrl+点击、Cmd/Ctrl+Enter 全部无效。浏览态里 Cmd+点击是真链接、能开新标签，面板里反而不能。

**建议**：`activate(item, event)` 里读修饰键，`window.open(url)`；行尾加「⌘⏎ 新标签」提示。

## P1 · 还没学到的 Arc 机制

### 9. 没有 frecency（最近 / 最常用）

`linkHits`（`SearchBar.vue:157-164`）是 `includes` 过滤 + 按住分组声明顺序，空面板也只有「搜索历史 + 命令」。
而 Arc 之所以「快」，一半功劳在候选是按你**实际打开过什么**排序的——这也是「学习 Arc 交互」里最值钱、目前完全没做的一块。

**落地**：`storage.local` 存 `{ [linkId]: { n, at } }`（本机、不上云、不进导出），打开链接时 `n++`，
排序用简单衰减 `score = n / (1 + 距今天数)`。命令面板顶部多一块「最近打开」，空面板第一屏就是它。
顺带解决第 15 条：面板默认展开时才不是一屏命令。

### 10. 没有 Tab 切模式

Arc 的签名交互是「一个输入框 + Tab 切模式」。现在换成了要背的 `/ gg gh` 暗号（`utils/search.ts:16`）。

**建议**：面板打开时 Tab 在「全部 → 链接 → 命令 → 历史 → 搜索」之间循环，输入框里显示当前 scope chip，Enter 执行。
前缀别名降级成进阶用法。代价是 Tab 不再离开输入框——而面板打开时本来也不打算用 Tab 去别处。

### 11. 结果行信息量偏低 / 缺匹配高亮

链接行右侧目前只显示组名，可以再给一列域名；命中片段做高亮。两处都是低成本、立刻能感知的改动。

### 12. 分组不能拖拽排序

只能拖链接（`LinkSections.vue:55`），分组顺序固定。Arc 的 spaces 可拖。

### 13. 中文拼音 / 首字母匹配

现在只匹配 title 与 url 子串。「掘金」打 `jj`、『知乎』打 `zh`（靠 zhihu.com 侥幸命中）这类结果全靠 URL 里有拼音。
要做就加一层拼音首字母索引，不做也说得过去——优先级低于前几条。

## P2 · 视觉 / 细节

### 14. 首屏会闪一次「天气 / 查位置」卡片

天气没返回之前，右栏渲染的是另一张带输入框的「天气 · 查位置…」卡片，数据到了再整块换成天气卡片（对比截图 01 / 02），
右栏高度和内容都会跳一下。新标签页一天开几十次，这个跳动每天会被看见几十次。

**建议**：加载态用和天气卡片等高的骨架，或干脆延后渲染第二张卡。

### 15. 面板一打开就压住一半链接

因为 `@focus` 就展开（`:365`）+ 挂载即 focus（`:338-341`），每次开新标签页看到的第一屏是 13 条命令的下拉，
「常用 / 开发 / AI / 资讯」四组被整块盖住（截图 01）。
如果这就是「面板即主界面」的设计意图，那没问题；否则建议空输入时只列「最近打开的 5 条」（配合第 9 条），命令收进 `>` 前缀。

### 16. 编辑态里每格的 `×` 离名字太远

格子 `minmax(170px, 1fr)`，`×` 靠右对齐，宽屏 6 列时和它所属的链接视觉脱节。建议 hover 时才出现，或让它紧贴文字右侧。

### 17. 弹窗没有焦点陷阱，Esc 只在输入框里生效

`LinkDialog.vue` 的 Esc 绑在三个 input 上（`:122 / 144 / 159`）：点到弹窗空白处再按 Esc 不会关；
Tab 也能跑到遮罩后面的链接上。

**建议**：window 级 Esc + 简单 focus trap。

### 18. 弹窗允许保存垃圾网址

`save()` 走 `normalizeUrl`（`utils/url.ts:1-6` 无条件补 `https://`），输入「随便写点东西」会存成 `https://随便写点东西`。
用 `looksLikeUrl` 拦一下，或至少给个红字提示。

### 19. Toast 只有一格，且没有 aria-live

`App.vue:184-190` 把 `storageError` 和 `toast` 挤在同一个槽位，前者是常驻的，会把后者顶掉。加上 `aria-live` 更完整。

### 20. 命令面板的无障碍是空的

输入框没有 `role="combobox"` / `aria-expanded` / `aria-activedescendant`，面板没有 `role="listbox"`，
屏幕阅读器读不到「现在是第几项、总共几项」。

## 隐私 / 文档与实际行为不符（上商店会被问）

### 21. 搜索历史实际写进了 `storage.sync`

`useNavData.ts:218 / 309` 走的是 `storage.read/write`，也就是 `chrome.storage.sync`——**搜索词跟着浏览器账号上云**。
而 `docs/privacy.md` 的表格里写的是「浏览器搜索历史 … 只存在浏览器本地存储里」。

要么把 history 挪到 `readLocal/writeLocal`（我倾向这个：搜索词没有跨设备同步的必要），要么改文档。

### 22. 「打开新标签页就往站点要 favicon.ico」没有体现在隐私文档里

`SiteCard.vue:17-18`：凡是没有浏览器缓存图标的链接，都会去请求 `站点/favicon.ico`，**不需要 host 权限、不需要用户点任何按钮**。
而 `docs/privacy.md` 里「你添加的网址」那行写的是「只在添加链接时，且仅针对你授权的那一个域名」。

实际行为是：新标签页一打开，就会对你导航里所有还没有图标的站点各发一次请求（失败记 7 天）。

这不是要改行为（`docs/design.md` 里对这条的取舍写得很清楚），但**隐私文档必须如实描述**，
否则和「不申请、不发送」的整体叙事自相矛盾。
