# Cool Nav

极简新标签页，Chromium/Edge 扩展（Manifest V3）。纯本地、无后端，不收集任何数据。

## 功能

- **搜索框**：默认 Bing，可切换 Google / GitHub；前缀直达（`gg` / `gh`）；输入像网址直接跳转；本地搜索历史
- **分组快捷方式**：左侧栏按分组导航，点一下锚定到中栏对应列表（高亮只认「你点的那一下」和「滚动的落点」）；中栏是白卡片里一格一格的站点（logo + 名称，不写描述），一行自动排 3~4 格。
  图标依次尝试：你自己填的图标 → 浏览器缓存的 favicon → 站点自己的 `/favicon.ico` → 首字母色块（颜色由域名决定，同站恒定）。
  浏览器缓存里没有（也就是你还没在这个浏览器里打开过那个站）才会走第三步，所以看不到 logo 通常不是网速问题；
  还有一部分站点把图标放在 `/logo.svg` 这种非根目录位置，猜不到——编辑态里有「**补全图标**」：
  一次授权后逐个访问这些站点、读页面里自己声明的图标并写进链接，之后就不再依赖浏览器缓存
- **背景**：默认 Bing 每日一图（第一次会问一次 bing.com 的权限，不给就一直用纯色底），也可以填一个自己的图片地址。
  纯色底不是一个死灰色——它跟着搜索引擎换，走孟菲斯那套高饱和粉彩（Bing 天蓝 / Google 亮黄 / GitHub 薄荷）。
  每日一图支持轮换节奏（每次新开 / 每小时 / 每天 / 不切换），换图带 900ms 交叉淡入；**扩展本身不带任何图片资源**
- **可读性**：背景图只铺在顶部搜索那一条，往下就是纯色，所以整页不需要任何蒙版
- **亮暗色**：右上角一键切；设置里还能选「跟随系统 / 浅色 / 深色」。两套色板写在同一个 `light-dark()` 里，靠 `color-scheme` 切换，不存在两份色值对不上的问题
- **编辑态**：按 `E` 或点右上角那支铅笔（一直显示，不再只在 hover 时出现）进入，可增删改链接、拖拽排序
- **键盘导航**：`Tab` 按顺序走，`←→↑↓` 按屏幕位置在链接间移动，`Enter` 打开；焦点环走强调色
- **右侧信息栏**：时间 / 日期 / 农历（含干支生肖）+ 节日 + 天气（当前温度与今日高低）+ 工作日与**补班**（带假期名）+ 黄历宜忌
- **天气位置**：**不申请定位权限**，直接按出口 IP 推断城市（城市级精度，对天气够用），卡片上标明「按出口 IP 推测」；`settings.city` 随时可以手填定死，手填后就不再走 IP
- **数据**：`chrome.storage.sync`，跟随浏览器账号跨电脑同步；图标只存 URL，不落库；
  别的标签页或设备改了数据，这边会跟着变（本地有待写入的改动时不抢）
- **备份**：编辑态可导出 / 导入 JSON

## 开发

```bash
npm install
npm run dev      # 普通网页里预览：无扩展 API，图标走色块兜底，数据存 localStorage
npm run build    # 产物在 dist/，同时就是一个可直接加载的扩展目录
```

## 装到 Edge

1. `npm run build`
2. 打开 `edge://extensions`，打开「开发人员模式」
3. 点「加载解压缩的扩展」，选择 `dist/` 目录
4. 新标签页就是它了

## 快捷键

| 按键 | 作用 |
| --- | --- |
| `/` 或 `Cmd/Ctrl + K` | 聚焦搜索框 |
| `↓` | 搜索框里按：直接进第一条链接（有历史联想时则是选历史） |
| `←` `→` `↑` `↓` | 焦点在链接上时，按屏幕位置在链接间移动 |
| `Enter` | 打开聚焦的链接 |
| `E` | 切换编辑模式 |
| `Esc` | 关弹窗 / 退出编辑 / 从链接回到搜索框 / 清空搜索框 |

## 数据与配额

`chrome.storage.sync` 的限额是总量 100KB、单条 8KB。链接只存标题和 URL，图标不写进存储，
所以几十到几百条都不会碰到上限。真超了页面底部会给出提示，先导出备份再精简。
写入内容没变时不会重复写；撞上「写得太频繁」这类限流会自动重试，不会把这几分钟的编辑丢掉。
如果同步里的数据读不出来（比如跨设备写坏了），页面回退到预置链接并且**不覆盖**原数据。
数据结构换过两轮，读进来都认：`version: 1` 的旧分组直接沿用（只补写版本号），`version: 2` 那份铺平的链接列表会被包进一个「常用」分组，读到时顺手落盘成新结构。

天气、地理编码和调休日历缓存在 `storage.local`（天气 30 分钟、调休 7 天），不参与同步也不进导出。

每日一图只缓存「一批图片地址 + 日期」到 `chrome.storage.local`，图片本身不落库，也不进导出的 JSON。
公开接口一天只请求一次，取不到就退回纯色底。

## 设计

完整的决策记录、数据模型和踩坑在 [docs/design.md](docs/design.md)，下面是速览。

- **版式**：顶部一条背景图带搜索框（高 `clamp(200px, 26vh, 276px)`，搜索框 850×55），下面三栏——160px 分组侧栏 + 自适应中栏 + 270px 信息栏，左右两栏吸顶；容器 `max-w-1400`
- **字号**：对齐参考站，正文 14px、分组侧栏 16px、分组标题 18px、站点名 14px / 600、次要信息 12px
- **背景两层**：图片层 + 底色；图片层用 `<Transition>` 做 900ms 交叉淡入，叠加 52s 极慢推近，图片取不到（或没给权限）就是底色——一个跟着搜索引擎换的纯色（`--hero-tone`）
- **图标**：`C + 出走的箭头`。16px 单独用简化版（只留 C，工具栏那一档才不会糊成蓝点），48 / 128 用完整图形；
  6 套备选留在 `docs/logo-options.html`
- **动效**：入场错峰上浮 620ms，`prefers-reduced-motion` 下全部关闭
- **踩过的坑**：入场动画的 `animation-fill-mode` 只能用 `backwards`。用 `both` 会让 `transform` 一直挂在元素上，
  该元素就成了层叠上下文，下拉面板的 `z-index` 会被困在里面，站点图标会压到面板上面

## 已知边界

- **没有任何全量 host 权限**：装的时候不会出现「读取所有网站数据」。两处用图 / 用网的能力都是按需申请——
  每日一图要 `bing.com`、抓标题要你当时添加的那个域名，都只在用到的那一刻问一次。不给每日一图权限就一直是「随引擎变的纯色底」。
  `npm run dev` 的网页环境跨域拿不到每日一图，抓标题也会回退成域名
- 天气和调休依赖外部接口：天气走 Open-Meteo（只发经纬度或城市名）、反查地名走 BigDataCloud、调休走 [holiday-cn](https://github.com/NateScarlet/holiday-cn)（按国务院通知手工维护）。取不到时天气那一格显示原因并给出「手动设置城市」的入口、调休退回「周末＝休息」的规则，页面其余部分不受影响；农历和黄历由浏览器内置历法 + 本地表算，不联网
- 位置是**按出口 IP 推断**的：出差、挂代理、公司出口在别的城市时会推错，城市不对就在右栏手填一个（手填优先，且不会再去查 IP）。之所以不用浏览器定位，是因为 Chromium 在系统定位不可用时会退回 Google 的定位服务，这个服务在国内不可达，即使把系统权限全开也只会拿到「设备定位不可用」——不如省掉这个权限和这套不确定性
- 不支持手机端：手机浏览器装不了自制扩展，这是当初主动砍掉的范围
- 没有回收站，删除不可撤销，兜底手段是导出 JSON
- `docs/seed-links.json` 是官方预置之外的备选链接池（35 条公开站点），不参与构建，不需要可直接删
